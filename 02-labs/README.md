# 02-labs 实操实验沙盒

## 目录职能说明

**学框架不敲代码、不看真实日志、不造报错就是耍流氓！**  
这里是你的代码练手操练场，与外部项目环境彻底隔离。

- `playground/`：随手测试代码、临时脚本验证、一次性探索 Demo。
- `milestones/`：按章节/里程碑组织的正式实践工程（渐进式切片与三层角色隔离）。
- `open-source/`：权威开源仓库挂载与源码切片镜像（真实开源工程深度对账基准）。

---

## 🏛️ 三大实操铁律与工程组织规范

为杜绝“把演示业务当成框架主角”、“单文件反复覆盖抹杀认知演进”以及“闭门造车写假玩具”的通病，`02-labs/` 强制执行以下三大铁律：

### 1. 真实开源工程锚定与源码深潜铁律 (Real-World Open-Source Grounding)

当研学新技术存在成熟的官方或生态开源项目时（如 LangGraph 官方 Examples、vLLM 推理服务、Dify 编排引擎），**严禁脱离工业界真实代码自嗨手捏脱离实际的假接口**！

- **开源工程落盘目录**：在 `02-labs/open-source/<project-name>/` 下通过浅克隆引入真实项目：
  ```bash
  # 推荐使用浅克隆拉取基准仓库（避免体积膨胀）
  git clone --depth 1 <repo_url> 02-labs/open-source/<project-name>
  ```
- **源码探针与双向比对**：
  - **断点与探针**：在开源源码关键生命周期 Hook 处直接注入探针打印或断点调试；
  - **切斯特顿栅栏比对**：学习者手撕的 `milestones/` 切片，必须对照开源库的实现，回答：“为什么开源框架要用三层抽象而非直接调函数？它解决了什么生产防御性问题？”

---

### 2. 工业级真实生产场景与抗压实战案例铁律 (Production-Grade Real-World Scenarios)

**彻底淘汰“查天气/猫粮客服/假Todo待办”等悬浮的代入式玩具案例 (Toy Cases)！**  
代入式玩具案例只能糊弄初学者，一到高并发、断网、数据持久化就全面瘫痪。每个核心知识模块必须提供**至少一个真刀真枪的工业级落地案例 (Production Case)**，必须具备**生产四要素**：

| 要素维度 | 规范要求与技术落盘 |
|---|---|
| **1. 真实复杂业务痛点** | 解决真实工业问题：如分布式长事务补偿 (Saga)、全链路断点续传、高并发防重幂等锁、企业级多租户隔离、敏感信息防泄漏过滤。 |
| **2. 真实生产组件协作** | 杜绝内存变量 mock！必须真实对接组件（如 SQLite/PostgreSQL 状态快照、Redis 锁与缓存、SSE 协议流式传输、真实中间件拦截器）。 |
| **3. 极端异常与抗压破坏** | 故意注入下游网络超时、依赖服务 Crash、Token 突发溢出截断、并发竞争，验证框架的**熔断、重试、回滚与自愈能力**。 |
| **4. 生产级可观测性沉淀** | 必须输出结构化日志（含 Trace ID 全链路跟踪）、生命周期事件耗时、内存状态快照，提供可核验的物理证据。 |

---

### 3. 三层角色物理隔离规范 (Three-Tier Sandbox Structure)

每个章节的复杂实验工程，按角色清晰拆分目录：

```text
02-labs/milestones/<chapter-name>/
├── 1-runtime/          # 智能体/框架宿主环境 (主控进程、CLI、状态图入口、启动脚本)
├── 2-harness/          # 挂载的外挂装备 (自定义工具、中间件配置、存储适配器、Prompt模板)
└── 3-target/           # 演示靶场载体 (分为受控极简靶场 vs 工业级生产靶场)
```

---

### 4. 渐进式演进：从最简内核到生产防线全武装 (Core-to-Hardened Evolution)

掌握框架的黄金路径是：**“简单例子快速吃透核心内核 ➔ 渐进式叠加周边能力 ➔ 用户确认后再按需全武装生产要素”**。  
严禁在同一个文件上反复修改覆盖，强制拆解为带编号的独立渐进式文件：

```text
02-labs/milestones/<chapter-name>/
├── 01-minimal-core.ts         # 阶段 1 (默认必做)：简单例子破局核心 (剥离一切外部干扰，只咬碎最纯粹的状态机与核心API)
├── 02-harness-injected.ts     # 阶段 2 (默认必做)：挂载中间件与工具 (验证事件拦截Hook、工具调用与上下文组装)
├── 03-production-hardened.ts   # 阶段 3 (按需进阶)：生产防线全武装 (核心之外全要素加满：真实DB事务、并发防重、安全脱敏、Trace追踪)
├── 04-chaos-resilience.ts     # 阶段 4 (按需进阶)：极端抗压与容错自愈 (主动注入断网超时、Token突发溢出、死锁竞争验收)
└── run-demo.sh                # 统一启动入口 (支持 ./run-demo.sh 01, ./run-demo.sh 03)
```

> 💡 **节律控制铁律**：初期文档与沙盒实验，**先不要考虑阶段 3 和 4 的生产防线全武装**！必须先把阶段 1 和 2 的核心功能彻底跑通吃透。只有当学习者明确表态“核心吃透了，带我上演进防线”时，再解锁并生成阶段 3 和 4 的生产级代码。

#### 🛡️ 阶段 3 进阶武装清单 (按需解锁)：除了核心功能外，必须武装的 5 大生产要素

| 生产要素维度 | 为何不可或缺 (Beyond Core) | 阶段 3 必须落地的代码防线 |
|---|---|---|
| **1. 稳定性与容错** | 生产环境没有 100% 可靠的下游服务 | 指数退避重试、降级兜底 (Fallback)、断路熔断、优雅停机与资源释放 |
| **2. 安全性与隔离** | 防范提示词注入与越权篡改 | 敏感信息脱敏 (PII Scrubbing)、多租户上下文隔离、工具调用最小权限执行 |
| **3. 并发与资源管控** | 高并发时内存雪崩与 Token 爆仓 | 分布式幂等防重锁 (Idempotency Key)、Token 预算熔断、滑动窗口压缩、流式背压 |
| **4. 持久化与事务一致** | 进程挂掉或网络断开导致状态全丢 | 真实数据库 Checkpointer (SQLite/PostgreSQL)、WAL 机制、分布式事务补偿 (Saga) |
| **5. 全链路可观测性** | 线上排障犹如盲人摸象 | 结构化 JSON 审计日志、OpenTelemetry 全链路 Trace ID 串联、核心性能度量指标 |

- **增量注释要求**：每个演进脚本顶部，必须明确写出【本阶段认知跃迁与上一阶段的增量对比】；
- **回溯自由**：学习者随时可以一键运行任何历史阶段的代码，看清架构是如何从一个简单的核心例子，一步步进化为无懈可击的企业级生产防线的！
